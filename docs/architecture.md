# Архитектура

## Компоненты

`skills/` содержит четыре независимых Agent Skills:

- `kotoba-settings` — профиль, диагностика и настройки;
- `kotoba-lesson` — выбор материала и проведение урока;
- `kotoba-test` — адаптивная проверка знаний;
- `kotoba-anki` — опциональная интеграция Anki.

Это структура Codex, дополняемая корневым `AGENTS.md`. Bionic использует один самодостаточный маршрутизирующий скилл `bionic/kotoba/SKILL.md`. Он не требует поддержки `AGENTS.md`, а повторяемые операции делегирует `tools/kotoba_bionic.py`; каноническое состояние у клиентов общее.

Основной режим не требует отдельного рантайма: агент читает и изменяет файлы по `docs/state-format.md`. Опциональный `tools/kotoba_state.py` выполняет те же изменения детерминированно, если пользователь выбрал Python-режим. Модель отвечает за диалог и педагогическое решение, а формат хранения остаётся одинаковым в обоих режимах.

`curriculum/catalog.json` содержит стабильные идентификаторы и зависимости материала. Каталог не является полным курсом: это стартовый вертикальный срез для проверки учебного цикла.

## Состояние ученика

После инициализации создаются:

- `learner/profile.json` — идентичность и исходные предположения;
- `learner/settings.json` — цель, время, фуригана и Anki;
- `learner/mastery.json` — агрегаты по учебным элементам и режимам;
- `learner/events.jsonl` — добавляемый журнал событий.

Самооценка получает статус `reported_known`. Ошибка переводит элемент в `learning`. Статус `mastered` требует трёх последних результатов со средним не ниже `0.8`.

## Поток занятия

1. `$kotoba-settings` создаёт профиль и диагностику.
2. `$kotoba-lesson` выбирает доступную тему с учётом зависимостей и прогресса.
3. Результаты записываются по стабильным ID.
4. `$kotoba-test` проверяет разные виды знания отдельно.
5. При включённом Anki `$kotoba-anki` создаёт подколоду урока и тематические теги.

## Режимы исполнения

- `runtime-free` — режим по умолчанию для Codex и Bionic: используются только файловые инструменты агента;
- `python-enhanced` — опциональные CLI-команды, проверяемые преобразования состояния и поставляемый адаптер AnkiConnect;
- `compact-session` — Bionic-команды `begin` и `finish`, использующие `tools/kotoba_session.py` для короткого производного `learner/context.json`;
- `MCP` — будущие или внешние адаптеры, которые должны соблюдать тот же формат и правила подтверждения.

Автоматическая запись в Anki не относится к базовому режиму. Без Python или доступного Anki MCP скилл создаёт только предварительный просмотр.

`learner/context.json` не является источником истины. Он восстанавливается из профиля, настроек, mastery и уроков; `events.jsonl` не загружается в snapshot.

## Границы MVP

- Проект не содержит собственного TTS или распознавания речи. В Bionic можно отдельно выбрать voice-модель и включить её автоматическую загрузку.
- Автоматическая загрузка бесплатных репозиториев и MCP пока не реализована.
- Bionic используется как оболочка и самостоятельно управляет локальной моделью; внешний LM Studio API проекту не требуется.
