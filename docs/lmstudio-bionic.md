# LM Studio, Bionic и Bonsai

В этой конфигурации LM Studio отвечает за локальную модель и API-сервер, а Bionic даёт модели доступ к Code Project и его файлам. Все действия в LM Studio выполняются через интерфейс; команды `lms` не нужны.

## Настройка LM Studio через интерфейс

1. Запустить LM Studio.
2. Если вкладка **Developer** не видна, открыть **Settings → Developer** и включить Developer Mode.
3. Во вкладке **Discover** найти Bonsai или другую подходящую instruct-модель и скачать совместимую с компьютером сборку.
4. Открыть **Chat** или **Developer**, выбрать скачанную модель и загрузить её в память. Начать с автоматических параметров; при нехватке памяти уменьшить context length или GPU offload.
5. Открыть вкладку **Developer** и включить переключатель **Start server**.
6. Оставить сервер привязанным к localhost. Стандартный адрес совместимого API — `http://localhost:1234/v1`.
7. Если Bionic требует API key, использовать значение, которое допускает его форма для локального провайдера. Если в LM Studio включена аутентификация, создать токен на странице Developer и указать его в Bionic.

Не включать доступ по локальной сети, CORS или внешний bind без отдельной необходимости: для Bionic на том же компьютере достаточно localhost.

## Bionic Code Project

1. Открыть Bionic и добавить провайдер LM Studio/OpenAI-compatible.
2. Указать базовый адрес `http://localhost:1234/v1` и выбрать загруженную модель.
3. Создать Code Project, выбрав корень этого репозитория.
4. Убедиться, что агент имеет право читать и изменять файлы проекта.
5. Начать с промпта:

```text
Прочитай AGENTS.md, docs/state-format.md и skills/kotoba-settings/SKILL.md. Настрой мне курс японского и проведи короткую входную диагностику. Работай без Python и сохраняй состояние файловыми инструментами.
```

Для следующего урока явно просить прочитать `skills/kotoba-lesson/SKILL.md`, а для теста — `skills/kotoba-test/SKILL.md`.

Поскольку автоматическое обнаружение Agent Skills зависит от конкретной оболочки, явное указание пути к `SKILL.md` является базовым совместимым режимом проекта.

## Требования к локальной модели

- понимание русского и японского;
- контекст, вмещающий активный скилл, состояние и текущий урок;
- надёжное следование инструкциям и работа с файловыми инструментами;
- поддержка structured output или tool use желательна, но не заменяет проверки файлов;
- более низкая температура для изменений состояния и более свободная генерация для диалоговых упражнений.

Если Bonsai нестабильно изменяет файлы, использовать её для учебного диалога, а состояние вести через Codex либо опциональный `tools/kotoba_state.py`. LM Studio сама по себе генерирует ответы, но файловые действия выполняет агентная оболочка.
