# LM Studio, Bionic и Bonsai

## Bionic Code Project

1. Открыть LM Studio и убедиться, что нужная локальная модель установлена.
2. Открыть Bionic и создать Code Project, выбрав корень этого репозитория.
3. Выбрать Bonsai или другую локальную модель.
4. Начать с промпта:

```text
Прочитай AGENTS.md и skills/kotoba-settings/SKILL.md. Настрой мне курс японского и проведи короткую входную диагностику. Для изменения состояния используй tools/kotoba_state.py.
```

Для следующего урока явно просить прочитать `skills/kotoba-lesson/SKILL.md`, а для теста — `skills/kotoba-test/SKILL.md`.

Публичная документация Bionic пока не гарантирует автоматическое обнаружение Agent Skills, поэтому явное указание файла является совместимым режимом MVP.

## LM Studio как сервер

LM Studio можно запустить как локальный API-сервер:

```bash
lms server start
lms load
```

Сам сервер генерирует ответы, но не исполняет содержимое `SKILL.md` и команды файловой системы без агентного клиента. Bionic предоставляет такую агентную оболочку для Code Project. Альтернативный прямой клиент LM Studio API или MCP-адаптер запланирован как следующий слой.

## Каталог скиллов LM Studio

Команда ниже копирует скиллы в `~/.lmstudio/skills`:

```bash
python3 tools/install_skills.py --target lmstudio-user
```

Этот путь предназначен для совместимого стороннего skill-loader плагина; обычный LM Studio не обязан автоматически читать его. Без загрузчика использовать Bionic и явные пути к `SKILL.md`.

## Требования к локальной модели

- достаточное понимание русского и японского;
- контекст, вмещающий активный скилл, состояние и текущий урок;
- надёжное следование инструкциям и, для автоматических команд, tool use;
- низкая температура для операций с файлами и более свободная генерация только в диалоговых упражнениях.

Если Bonsai плохо вызывает инструменты, оставить модели учебный диалог, а команды `kotoba_state.py` выполнять вручную или через более надёжную модель-оркестратор.
