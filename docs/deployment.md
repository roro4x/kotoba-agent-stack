# Развертывание

## Вариант 1: Codex без Python

Требуется только Codex и локальная копия репозитория.

1. Открыть каталог проекта в Codex.
2. Оставить скиллы в `skills/` и явно просить прочитать нужный `SKILL.md` вместе с `AGENTS.md`.
3. Либо для глобальных команд скопировать каталоги `skills/kotoba-*` через файловый менеджер:
   - macOS/Linux: в `~/.agents/skills/`;
   - Windows: в `%USERPROFILE%\.agents\skills\`.
4. Перезапустить Codex, если новые `$kotoba-*` не появились.
5. Запустить `$kotoba-settings` или использовать стартовый промпт из README.

Состояние будет изменяться файловыми инструментами агента по `docs/state-format.md`.

## Вариант 2: Bionic с рекомендуемой Python-обвязкой

Требуются Bionic, этот репозиторий и Python 3. Сторонние Python-пакеты не нужны. Отдельный LM Studio или локальный API-сервер не нужен: Bionic сам скачивает и запускает выбранную модель.

1. В Bionic выбрать подходящую локальную модель и дождаться её автоматической загрузки.
2. Открыть этот каталог как Code Project.
3. Вставить prompt из `bionic/INSTALL_PROMPT.md`. Он запускает `python3 tools/kotoba_bionic.py setup --run-tests` и выводит точный путь скилла.
4. Через настройку установки скиллов выбрать конкретный каталог `bionic/kotoba`. Он не требует `AGENTS.md`. Не выбирать общий каталог `bionic/`: Bionic может не искать скиллы во вложенных каталогах.
5. При необходимости выбрать voice-модель и включить **Auto load voice model**.
6. В новом чате запустить установленный `kotoba`.

Подробности и диагностика находятся в `docs/bionic.md`. Внешний модельный сервер не используется.

Без Python Bionic остаётся совместим с файловым форматом из `docs/state-format.md`, но теряет детерминированные пакетные записи и автоматический компактный snapshot/checkpoint. Этот вариант следует считать резервным.

## Вариант 3: CLI без агентной оболочки

Дополнительно требуется Python 3. Сторонние библиотеки не нужны.

Проверка установки:

```bash
python3 --version
```

На Windows команда может называться `py -3`; в таком случае заменить `python3` в примерах. Для ведения курса использовать `tools/kotoba_state.py`. Для установки скиллов из терминала — `tools/install_skills.py`.

## Вариант 4: Anki

Для ручного режима достаточно preview, подготовленного `$kotoba-anki`, после чего карточки добавляются пользователем.

Для автоматического режима дополнительно нужны:

- Anki;
- дополнение AnkiConnect;
- Python 3 либо совместимый Anki MCP с явным доступом к локальному Anki.

Перед любой записью сначала создать preview. Автоматическое применение выполнять только после подтверждения пользователя. Текущий поставляемый адаптер `tools/kotoba_anki.py` использует Python 3 и стандартную библиотеку.

## Что выбрать

| Сценарий | Python | Bionic | AnkiConnect |
|---|---:|---:|---:|
| Codex, уроки и прогресс | нет | нет | нет |
| Bionic, рекомендуемый компактный режим | да | да | нет |
| Bionic, резервный файловый режим | нет | да | нет |
| Детерминированные CLI-команды | да | нет | нет |
| Автосинхронизация Anki текущим адаптером | да | нет | да |

Codex и вариант Bionic можно использовать попеременно: источником истины остаются файлы репозитория.
