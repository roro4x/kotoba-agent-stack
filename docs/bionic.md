# Bionic, локальные модели, скиллы и голос

Bionic самостоятельно скачивает, загружает и запускает локальные модели. Для работы Kotoba не нужно отдельно устанавливать LM Studio, запускать API-сервер или настраивать OpenAI-compatible provider.

## Рекомендуемое окружение

| Компонент | Требование |
|---|---|
| Bionic | Code Project с корнем репозитория |
| Основная модель | локальная instruct-модель с русским, японским и tool use |
| Python | Python 3, рекомендуется для состояния и checkpoint |
| Python-пакеты | не нужны; `pip install` не выполнять |
| Node.js, Docker, база данных | не нужны |
| LM Studio | не нужен |
| Voice-модель | опционально, управляется Bionic |

Python не является частью формата состояния: при его отсутствии агент может изменять JSON/JSONL файловыми инструментами. Однако для стабильной работы в чатах с контекстом до 32k рекомендуется разрешить Bionic запускать поставляемые Python-скрипты.

Проверить окружение из корня проекта:

```bash
python3 --version
python3 tools/kotoba_bionic.py setup --run-tests
python3 tools/kotoba_bionic.py doctor
```

`setup` создаёт только необходимые каталоги и проверяет проект; профиль ученика он не создаёт. `doctor` должен вернуть `"ready":true`. На Windows команда Python может называться `py -3`; тогда заменить `python3` во всех командах и в локальной копии Bionic-скилла.

## Code Project и основная модель

1. Открыть Bionic и выбрать подходящую локальную instruct-модель, например Bonsai.
2. Дождаться, пока Bionic автоматически скачает и загрузит модель.
3. Создать Code Project, выбрав корень этого репозитория.
4. Разрешить агенту читать проект, изменять `learner/` и `lessons/` и запускать команды `python3 tools/*.py` из корня проекта.

Модель должна понимать русский и японский, следовать инструкциям и надёжно работать с файловыми инструментами. Для текущей архитектуры достаточно контекста 32k: snapshot намеренно ограничивает объём состояния. Если Bionic позволяет выбирать размер контекста, установить 32k либо максимальное поддерживаемое моделью значение не ниже него.

## Автоматизированная подготовка

После открытия Code Project вставить prompt из [`bionic/INSTALL_PROMPT.md`](../bionic/INSTALL_PROMPT.md). Он запрещает загрузку `AGENTS.md`, запуск LM Studio, создание профиля и установку пакетов; вместо этого запускается единая проверка окружения.

Скрипт автоматически проверяет:

- версию Python;
- наличие скилла, каталога и рабочих скриптов;
- синтаксис учебного каталога;
- права записи в runtime-каталоги;
- полный набор unit-тестов.

После успешного `setup` Bionic выведет абсолютный путь к `bionic/kotoba`. Выбрать именно этот каталог в интерфейсе установки скилла. Это единственный ручной шаг: проект не может надёжно изменить настройку скиллов Bionic изнутри Code Project.

Единый `kotoba` маршрутизирует настройку, урок, тест и Anki. Codex-версии остаются в `skills/`.

## Контекст до 32k

В начале чата единый скилл запускает `python3 tools/kotoba_bionic.py begin`. Команда выдаёт компактные настройки, слабые элементы, кандидатов и последний урок, не загружая полный журнал.

После чата с изменениями скилл вызывает один `finish`, который пакетно записывает результаты и обновляет checkpoint. Детали выбранных элементов выдаёт команда `items ID...`, поэтому модели не нужно читать весь каталог. Подробнее: [компактные чаты](session-workflow.md).

## Voice-модель

Для голосового режима выбрать voice-модель в настройках Bionic и включить **Auto load voice model**. Тогда Bionic будет автоматически загружать её без отдельного ручного запуска.

Это функция Bionic, а не собственный TTS-адаптер Kotoba. Доступные голоса и конкретное поведение воспроизведения зависят от установленной версии и настроек Bionic.

## Первый запуск

Начать можно с промпта:

```text
Используй установленный kotoba. Настрой мне курс японского и проведи короткую входную диагностику. Сохраняй прогресс после моих ответов.
```

В следующих чатах тот же `kotoba` самостоятельно выбирает режим урока, теста, настроек или Anki. Автоматически применять изменения Anki без явного согласия пользователя нельзя.

После настройки профиля проверить сохранение:

```bash
python3 tools/kotoba_state.py summary
python3 tools/kotoba_bionic.py begin
```

После чата, в котором изменились настройки, прогресс или урок, Bionic-скилл должен выполнить:

```bash
python3 tools/kotoba_bionic.py finish
```

Ответ `checkpoint skipped` при отсутствии изменений является нормальным.

## Проверка проекта

Перед первым использованием и после обновления скриптов выполнить:

```bash
python3 -m unittest discover -s tests -v
```

Ожидаемый результат — все тесты со статусом `OK`. Тесты работают во временных каталогах и не изменяют профиль ученика.

## Если что-то не работает

- `python3: command not found` — установить Python 3 или использовать системную команду `py -3`/`python`.
- Скилл не появился — устанавливать конкретный каталог `bionic/kotoba`, а не общий `bionic/`.
- `initialized:false` — профиль ещё не создан; запустить единый `kotoba` и попросить настроить курс.
- Состояние не обновилось — проверить право записи в `learner/` и запуск `kotoba_bionic.py finish`.
- Контекст кажется устаревшим — снова выполнить `kotoba_bionic.py begin`; он обнаружит незавершённый checkpoint.
- Anki недоступен — ограничиться preview и не утверждать, что карточки синхронизированы.

Если локальная модель нестабильно изменяет файлы, выполнять запись состояния детерминированными командами `tools/kotoba_state.py`; при повторяющихся ошибках использовать Codex для восстановления файлов.
